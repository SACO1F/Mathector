当前面向中国高中学生、家长和教师，采用 Kotlin + Jetpack Compose 开发 Android 原生 App，优先手机并适配平板和折叠屏。知识点使用内置高中词表及用户在高中模块下创建的自定义知识点，年级只允许高一、高二、高三；识别与分类验证以高中印刷题为起点，再扩大手写题覆盖。视觉继续参考 Apple 的克制层次、玻璃质感和自然回弹，同时遵守 Android 的返回、权限、文件与后台任务行为。

## 1. 产品定位和边界

产品定位：把纸面、图片和文件中的数学题，转换为可以校对、检索、组合、打印和继续编辑的个人题库。

核心价值链：三种方式录入 → 自动拆题 → 校对题干与公式 → 自动分类并人工修正 → 保存到题库 → 组成题集 → 排版并导出。

第一版应完整覆盖三种录入入口、结构化题目、分类与搜索、题集、PDF/DOCX 导出和 Apple 风格交互。图片及 PDF 为首批文件类型；DOCX 输入列入紧随其后的增量版本。不要把 OCR 结果直接视为已确认的题目，也不要把分类预测当作教学事实。

首次使用允许本地建立草稿并体验题库。账号主要服务于云同步、跨设备访问和云端任务归属。原题中的答案可以保存，但答案来源必须明确；自动解题、相似题推荐、复习计划、教师协作和公共题库作为后续功能。

## 2. 信息架构与主要页面

底部导航采用“题库 / 题集 / 我的”，旁边设置始终可发现的“添加”入口。点击添加，展示“拍照、相册、文件”三个动作。导入任务状态用独立的悬浮状态胶囊表示。

| 页面 | 核心内容 | 主要操作 |
| --- | --- | --- |
| 题库 | 搜索、待校对、最近添加、分类筛选、题目列表 | 添加题目、组合筛选、批量加入题集 |
| 导入预览 | 页缩略图、旋转与裁剪、题目区域框、选中页数 | 删除无关页、调整区域、确认识别 |
| 校对 | 原图与结构化题目对照、疑似错误、分类建议 | 修改公式、拆分/合并题目、确认保存 |
| 题目详情 | 完整题干、子题、图形、来源、分类、备注、原题答案 | 编辑、收藏、加入题集、查看原图 |
| 题集 | 用户创建的题集及题目顺序 | 选题、排序、移除、配置模板 |
| 导出预览 | 真实 PDF 分页、答案设置、空白答题区 | 调整排版、导出 PDF/DOCX、系统分享 |

Android 手机校对采用“原图/识别结果”切换和可展开原图；宽窗口的平板、横屏和折叠屏采用原图与编辑区双栏。根据当前窗口可用宽度选择布局，支持字体放大和分屏。原图和题干上的区域可相互定位。批量操作进入独立选择模式，底部显示“已选 N 题 / 加入题集”，避免每个题目都堆满按钮。系统返回先关闭键盘或临时浮层，再退出当前流程；未保存校对内容先持久化草稿，导航适配预测性返回。

## 3. 题目录入与识别

### 3.1 三种输入

拍照：支持单题、整页和连续多页；拍摄时提示模糊、反光、缺边与倾斜。支持透视矫正、裁边、旋转和温和增强。去阴影、去手写或清背景需要保留原图并允许撤销，不能损伤几何细线、角标和负号。

相册：支持 JPEG、PNG，多图选择；HEIC/HEIF 按设备解码能力处理，并准备受控转换回退。正确处理 EXIF 方向、颜色空间及云端图片加载失败。批量预览中可以调整顺序。缩略图按显示尺寸采样，原图按页处理，不同时把整批高分辨率图片解码到内存。

文件：首版支持数字 PDF、扫描 PDF 和图片文件；后续增加 DOCX。可选择指定页识别。数字 PDF 优先读取已有文本、坐标和可用结构，扫描页才执行完整 OCR；复杂数学内容可以局部回退至公式识别。加密 PDF 提示用户解锁或提供可读取副本。超出可配置的页数/体积上限时按批次处理，不能静默截断。

拍照以 CameraX 为默认基础，预览、拍摄与图像分析分工；分析限制频率，避免预览掉帧，结合可本地打包的图像处理实现裁边和透视矫正。点击拍照时才申请相机权限，拒绝后仍可使用相册和文件入口。[CameraX 官方文档](https://developer.android.com/media/camera/camerax)。

相册使用 Activity Result 的 PickVisualMedia/PickMultipleVisualMedia。系统 Photo Picker 不可用时，官方合约可以回退到 ACTION_OPEN_DOCUMENT；该流程只访问用户选择的图片。文件使用 Storage Access Framework 的 OpenDocument/OpenMultipleDocuments，通过 ContentResolver 读取 URI，不假设一定能取得真实文件路径。后台任务需要持续读取时，保存可持久化授权，或将选中文件导入应用私有存储，并处理原文件移动、删除和授权失效。[Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker)、[文件访问与持久授权](https://developer.android.com/training/data-storage/shared/documents-files)。

ML Kit Document Scanner 可作为有 Google Play 服务设备上的可选增强。它的扫描逻辑、模型和 UI 由 Google Play 服务动态下载，因此国内设备的默认扫描路径采用 CameraX 与本地处理。默认采集、登录和任务恢复流程均不依赖 Google Play 服务。[ML Kit 扫描要求](https://developers.google.com/ml-kit/vision/doc-scanner/android)。

### 3.2 处理流水线

输入校验 → 图像预处理或原生文件解析 → 版面检测 → 文字 OCR 和公式识别 → 阅读顺序恢复 → 大题/子题拆分 → 图形关联 → 结构校验 → 分类建议 → 校对草稿。

每一页可能包含标题、题干、选项、公式、图形、答案与页眉页脚。先理解版面，再识别和拆题。不能仅用题号正则截取全文；跨栏、跨页和重复子题号会使这种方案丢题。

题目采用有序内容块：文字、行内公式、独立公式、图片、表格、选项和子题。公式保存 LaTeX 源码和原始识别记录；几何图与坐标图首版保存清晰原图裁片，并记录来源页和区域位置。未经用户确认，禁止模型自行重绘几何图或补出题目条件。

商用数学 OCR 可以评估 Mathpix，它提供图像中的数学内容、区域和质量信息；自部署可以评估 PaddleOCR 的版面/文字能力与公式识别产线。是否采用哪家，由中文数学试卷基准、数据处理地域、并发、页成本和纠错耗时共同决定。[Mathpix 图像识别接口](https://docs.mathpix.com/reference/post-v3-text)、[PaddleOCR 公式识别官方文档](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/formula_recognition.en.md)。

多模态模型可以辅助阅读顺序、题目拆分、图文关联和分类，但不覆盖可追溯的原始 OCR。模型结构化输出必须通过字段、枚举、题目完整性及公式解析校验。来源中的文字属于待处理数据，不能成为模型或工具的执行指令。

### 3.3 校对和异常处理

对低置信度或规则检测到的异常进行定位提示，重点关注正负号、不等号、指数、分母、根号范围、变量、单位和几何标注。模型置信度不直接展示成准确率；在人工标注的验证集上校准后才制定分流阈值。

用户可用可视化工具编辑分数、根号、指数、上下标、方程组与矩阵，高级模式提供 LaTeX。修改后实时渲染，并保存修订记录。渲染成功只是语法检查，不代表识别内容正确。

低置信题进入待校对；高置信题允许批量预览确认。未确认的内容保存为草稿。导出含待校对题目时显示数量和定位入口，由用户明确选择是否继续。

任务状态：等待上传、上传中、等待处理、预处理中、识别中、生成草稿、待校对、完成、部分失败、失败、已取消。批处理显示已完成页/题，而不是虚构百分比。支持取消和只重试失败页；离开页面或重新启动后可以查看任务状态。

## 4. 自动分类、归档与检索

| 维度 | 表示方式 | 规则 |
| --- | --- | --- |
| 题型 | 选择、填空、判断、计算、解答、证明等 | 复合题的子题可以有不同题型 |
| 知识点 | 领域 → 章节 → 知识点层级 | 多标签，允许一个题覆盖多个知识点 |
| 年级 | 候选年级集合及主建议 | 结合课程体系和教材，不强制唯一 |
| 教材 | 教材版本、册次和章节映射 | 年级/章节需依赖教材版本，保留版本号 |
| 难度 | 基础、进阶、挑战 | 相对于所选年级/课程定义，是预测值 |
| 学习状态 | 未练、练过、掌握、待复习 | 表示用户学习情况，独立于客观难度 |
| 来源与个人标签 | 文件、页码、区域、导入时间、自定义标签 | 保留来源，不与知识点标签混为一谈 |

分类采用规则、知识点检索和模型建议结合。输入不仅是题干，还包括公式、子题和来源上下文。分类标签必须来自内置高中词表；无法判断的年级保留未选择状态。在界面显示“高二 / 导数概念与运算 / 进阶”等建议，让用户确认或修改；知识点可以通过标签按钮增删，支持多个。

题集的选题面板支持知识点、年级、难度组合筛选，以及标题、题干、公式和知识点搜索；每张卡片显示年级、难度、全部知识点和彩色标签，并保留 LaTeX 预览。年级为蓝色、知识点为紫色，难度按基础／进阶／挑战采用绿／橙／红色；未分类内容使用灰色。可跨筛选条件多选，确认后按选择顺序批量加入，已有题目不重复添加。

选题和题集使用同一套紧凑卡片，年级、难度与知识点标签前置并在同一行自然换行，下方依次显示标题和题干 LaTeX 预览。题集通过卡片右上角菜单排序或移除，点击卡片打开完整题目；添加入口固定在右下角，使用透明玻璃胶囊、蓝色加号和文字、背景模糊与按压回弹，避开系统导航栏。滚动列表末尾预留按钮高度与间距，确保试卷设置和导出操作完整可见。

题库也使用上述共享卡片，收藏与加入题集收进右上角菜单，示例／收藏／待校对状态通过紧凑标签显示。底部导航的选中背景在三个入口之间弹性滑动，图标和文字颜色过渡；主页面按切换方向同步横向移动并淡入淡出，支持运动中的连续切换。选题叉号及确认动作先等待面板下滑隐藏再关闭或提交，动画期间避免重复点击；系统返回与外部点击使用面板原生收回行为。

人工修改优先级高于后续自动分类。全库重新分类必须保留旧版本，不能覆盖人工确认。难度初期依据解题步骤、知识点组合和推理要求判断；以后可参考真实练习数据重新校准，但不能把某个学生的错题直接定为难题。

题库负责统一保存；题集负责组织。题目和题集是多对多关系，加入多个题集不复制题干。按“年级、题型、难度、知识点”组合检索，支持保存常用筛选条件。

搜索先实现中文关键词、标签与规范化公式片段检索。初期使用本地索引及 PostgreSQL 中适合中文分词的索引方案；题量或体验需求增长后再接专用搜索引擎。向量检索为语义搜索提供补充，不能代替公式检索。

重复识别先用文件哈希和规范化内容指纹检测，再用相似度提示。不同条件、数字、选项或图形的题不自动合并。用户决定复用已有题还是保留变式。

## 5. 题集、排版与导出

当前导出固定为 A4 单栏，支持用户填写试卷主标题、考试说明、考试时间（分钟）与满分，按题集保存，留空不显示。试卷主标题居中，时间和满分随后居中显示，考试说明支持多行；这些信息仅放在首页。题目按选题顺序生成大题编号，多个小题按（1）（2）连续编号，每道题重新起算，公式在原文字位置排版。标题和题干清理原大题题号，已有小题标记按顺序整理；多模态结果提取有序小题数组。题目标题、姓名日期、分类、来源附录、答案和页眉页脚不输出。后续可扩展分组和答题空白。

选择题的 A/B/C/D 选项根据标签、文字和公式的实际宽度排版，四项可以放下时横向铺开成一行，超出时采用 A/B、C/D 两行布局，长选项在列内换行。题库、编辑预览与 PDF/DOCX 导出均以题干为准，仅显示原文字位置的公式，不自动追加独立公式字段；没有题干的纯公式题目保留唯一公式内容。

默认 A4、单栏、18–20 mm 页边距、清晰黑白打印、题干约 11–12 pt。学生版默认不含答案；原题答案可以单独生成教师版或尾部答案页。没有原题答案时明确保持为空，不隐式生成答案。

| 格式 | 用途 | 生成方式 | 注意点 |
| --- | --- | --- | --- |
| PDF | 打印、分享和稳定版式 | 规范化题目 → 打印 HTML/CSS → 公式渲染 → 隔离环境中的浏览器打印 | 字体嵌入、图像分辨率、实际分页和答案隔离 |
| DOCX | 教师继续编辑、调整题目 | 同一内容模型 → Pandoc/文档生成 → Word 原生公式 OMML | 支持范围内公式可编辑，不支持公式有明确降级提示 |
| Markdown/LaTeX | 高级用户交换与备份 | 从结构化源导出 | 后续提供；不是首版普通用户的主要入口 |

Pandoc 的 DOCX 数学输出使用 OMML，可作为 Word 可编辑公式链路的基础，但复杂宏和所有公式的兼容性需要单独测试。[Pandoc 数学输出](https://www.pandoc.org/demo/example33/8.13-math.html)。

正文和公式尽量保持可选择的文本或清晰矢量，几何图使用原图裁片。图像不能简单通过提高 DPI 元数据假装变清晰。一般题目避免跨页；超过一页的大题按子题或自然段拆分并保留“续题”关联。双栏需检查公式、图形及选项宽度，必要时局部改为通栏。

PDF 预览展示已经生成的最终 PDF，分享的就是这份文件，因此页码和分页一致。DOCX 在 Word/WPS 等环境中可能重新排版，其参考预览不能被承诺为逐页完全一致。DOCX 导出前展示需要图片降级的公式数量，用户可返回修正或接受降级。

排版预检覆盖：公式渲染错误、超出页面、缺图、字体缺失、正文和答案混入、空白页、题号重复、超高题目及没有关联的子题。导出任务使用题目修订快照，导出时编辑题目不会让同一文档前后不一致。

Android 首版由后端生成规范 PDF/DOCX，客户端下载后用 PdfRenderer 或评估后的 Android PDF 组件按需预览 PDF 页面。保存文件用 ACTION_CREATE_DOCUMENT，让用户选择目标位置；分享用 FileProvider 提供 content URI 并授予临时读取权限。DOCX 可交由已安装的办公应用打开，并提供没有处理应用时的提示。[Android 文件分享](https://developer.android.com/training/secure-file-sharing/share-file)。

离线时可以浏览、校对、整理和查看已下载的文档；尚未执行的云识别和规范导出进入待处理队列。完整的离线数学 OCR 和高保真文档生成作为后续独立能力评估，不纳入首版前提。

## 6. Android 上的 Apple 风格视觉、悬浮状态栏与动效

视觉以内容可读为核心：浅色或深色中性背景、Android 系统字体与中文回退、大标题、明确层级、舒展留白和克制的强调色。Compose 使用可访问的 Material 组件行为和触摸能力，统一定制颜色、字阶、形状、间距与动效；图标使用适合 Android 的 Material Symbols 或许可明确的统一图标集。题干与公式卡片使用稳定的不透明背景，导航和操作层才使用玻璃材质。

初始设计令牌：8 dp 间距网格，页面水平留白约 16–20 dp，普通卡片圆角约 20–24 dp，导航与状态组件用胶囊形；题干约 16–18 sp，支持系统字体缩放。强调色以清晰蓝色为起点，深色模式单独校验。具体数值通过真机阅读测试调整，字体单位与布局单位不得混用。

“状态栏”区分三类：

- 系统状态栏显示时间、网络和电量，由 Android 系统绘制。App 采用 edge-to-edge 并适配图标明暗，在 WindowInsets 安全区域内绘制自定义浮层。系统状态栏与手势/三键导航区不能被应用操作遮挡。[Android WindowInsets](https://developer.android.com/develop/ui/compose/system/insets)。
- 底部悬浮导航条承载题库、题集和我的；添加按钮与导航在视觉上相关、操作上明确。
- 应用任务状态胶囊显示“正在识别 3/8 页”或“已生成 12 题，待校对 2 题”，点击进入任务详情，完成后可收起。

“透视质感”在本方案中定义为能看见模糊背景的玻璃层次与光学深度。采用背景透色/模糊、适度边缘高光、细微阴影和随背景变化的对比度。阅读区不做持续倾斜、摇晃或 3D 视差。

Android 玻璃组件采用“背景内容采样层 → 局部模糊/着色层 → 边缘高光与阴影层 → 清晰的文字图标层”。这可以保留背景透视感，同时让操作始终清晰。Compose 的 Modifier.blur 模糊的是被修饰内容，不能直接给导航容器加 blur 来获得正确的背景模糊，否则图标文字也可能变模糊。[Compose 图像模糊](https://developer.android.com/develop/ui/compose/graphics/images/customize)。

先评估 Haze 等有源代码和平台说明的背景模糊库，锁定与 Compose 配套的稳定版本，再封装自己的 GlassSurface；不在首版直接实现复杂折射着色器。Haze 的平台文档说明了 Android 12/12L 的适配和旧系统模糊的成本，必须在目标真机测试。[Haze 平台说明](https://chrisbanes.github.io/haze/latest/blur/platforms/)。

| 设备等级 | 产品策略 |
| --- | --- |
| Android 13+ 且性能合适 | 导航和任务胶囊使用局部背景模糊、透色、高光与阴影 |
| Android 12/12L | 测试通过后启用有限模糊，必要时降低采样质量或回退 |
| Android 8–11、低内存或用户选择简化 | 半透明/较实色面板、高光和阴影，关闭实时背景模糊 |

这些分级是本产品的保守选择，最终由稳定库版本、设备能力与实测决定。AndroidView/WebView 内容能否正确参与背景捕获需先验证；不适合捕获的阅读页使用更实色的浮层。

浮层必须为正文预留底部空间，最后一道题可以完整滚动到浮层上方；处理状态栏、摄像头开孔、系统手势/三键导航和输入法的 WindowInsets。校对键盘出现时将必要操作移至键盘上方并避免重复消费 insets。悬浮状态胶囊只在 App 内显示，不需要跨应用悬浮窗权限。

| 交互 | 预期动效 | 参数与实现原则 |
| --- | --- | --- |
| 按钮按下/抬起 | 轻微缩放并回弹 | 起点缩放约 0.97–0.98，反馈应立即发生 |
| 添加入口展开 | 底部面板连续展开 | 随手势速度释放，轻微回弹，不反复振荡 |
| 卡片打开详情 | 连贯的空间过渡 | 对应元素可衔接，长内容避免整体夸张缩放 |
| 拖动题目排序 | 跟手、占位、放手吸附 | 可中断，保持当前速度与位置连续 |
| 保存成功 | 克制的状态变化与触觉反馈 | 不播放遮挡内容的长动画 |

Compose 使用 spring 的 dampingRatio 和 stiffness 控制回弹，可先从 dampingRatio 约 0.8–0.9、stiffness 约 300–500 作为调参起点。按钮轻微缩放、面板展开、拖动吸附分别调参。拖动过程跟随手指，释放时带入速度；动画允许用户中途反向操作。弹簧稳定时间取决于参数与距离，不能当作固定时长。[Compose 弹簧动画](https://developer.android.com/develop/ui/compose/animation/customize)。

支持系统字体缩放、TalkBack、深色模式和高对比设置。尊重系统动画时长设置，App 另提供“简化动效”和“降低透明效果”偏好。简化时移除明显位移与回弹，降低透明时切换为高对比背景。Android 点击热区按至少 48×48 dp 设计；题目标签、任务进度和公式提供可理解的无障碍描述。

## 7. 技术路线与数据设计

### 7.1 平台与技术选型

主路线：Kotlin + Jetpack Compose 原生 Android。使用单 Activity、Jetpack Navigation 稳定版本、屏幕级 ViewModel、StateFlow 与 Repository；状态按生命周期收集。Room 作为本地持久化数据来源，DataStore 保存年级、教材、主题与动效偏好。复杂或复用业务才引入 UseCase。依赖注入可使用 Hilt。[Android 架构建议](https://developer.android.com/topic/architecture/recommendations)。

建议 minSdk 26（Android 8.0）作为首版支持下限；这是产品取舍，需结合目标用户设备确认。compileSdk/targetSdk 在启动开发与发布时按稳定 SDK 和目标渠道要求确定，不能长期锁在过期目标版本。Kotlin、Compose BOM、AndroidX 与后台依赖通过版本目录统一锁定。

| 模块 | 推荐实现 | 目的 |
| --- | --- | --- |
| 客户端 | Kotlin、Compose、ViewModel/StateFlow、Jetpack Navigation | 页面、交互与可恢复状态 |
| 本地数据 | Room、DataStore | 题库、草稿、任务、同步操作及偏好 |
| 网络与注入 | Retrofit/OkHttp、Coroutines、Hilt | 服务接口、取消、重试和依赖管理 |
| 输入与图像 | CameraX、Photo Picker、SAF、采样图像加载 | 拍摄、图片/文件选择、预览与内存管理 |
| 公式显示 | 本地 KaTeX/MathJax + 受限 Android WebView，评估原生替代 | 数学排版与离线阅读 |
| 持久任务 | WorkManager 与 Room 任务记录 | 上传/下载恢复、同步和约束条件 |
| API | Python FastAPI 的模块化单体 | 账号、权限、题目、题集、任务与配额 |
| 任务 | Redis + 成熟任务队列 + 独立 Worker | OCR 和导出异步执行、分页重试与取消 |
| 数据 | PostgreSQL | 题目关系、版本、分类、任务、同步状态 |
| 文件 | S3 兼容对象存储 | 原图、页图、图形裁片、导出文件 |
| OCR | 可替换的商用或自部署适配器 | 避免业务绑定供应商响应格式 |
| 导出 | 隔离的 HTML 打印 Worker、DOCX 转换 Worker | 控制字体、模板、资源和兼容性 |

初期保持模块化单体和少量 Worker，按真实负载扩展识别/导出处理，不预先拆为大量微服务。

Android 工程初期按 app、core（数据/网络/公式/设计组件）、feature（题库/导入/校对/题集/导出/设置）划分包；构建和协作有需要时再拆 Gradle 模块。当前正文公式使用离线 KaTeX，LazyColumn 仅组合附近可见项，网页实例离开组合时释放；正文或主题未变化时不重新加载。后续针对大题库评估公式位图缓存或原生行内渲染，进一步减少网页实例开销。

公式输入属于不可信内容，渲染时禁止任意 HTML、外链加载和无限宏展开，限制尺寸与长度。使用 KaTeX 时遵循 trust、maxExpand 等限制，并转义渲染错误消息。网页视图限制导航、网络和原生桥接范围。[KaTeX 安全说明](https://katex.org/docs/security)。

### 7.2 数据对象

| 对象 | 关键内容 |
| --- | --- |
| SourceDocument / SourcePage | 用户归属、原文件、哈希、页序、图像尺寸 |
| Question / QuestionRevision | 题目主记录、当前版本、校对状态、修订与操作时间 |
| QuestionBlock | 有序文字/公式/图形/选项/子题、来源页与区域、识别质量 |
| Asset | 原图裁片、格式、尺寸、存储引用与用户归属 |
| Taxonomy / LabelAssignment | 课程词表、教材映射、版本、分类置信、确认来源 |
| Collection / CollectionItem | 题集、题目关联、位置、分值与答题空白 |
| ImportJob / ExportJob | 状态、分页进度、失败原因、幂等键、取消信息 |
| ExportSnapshot | 题目修订与模板版本快照、产物文件 |
| SyncOperation / Tombstone | 离线操作标识、服务器版本、删除同步 |

导入层、OCR 适配器和分类层都输出到统一内容模型，客户端和导出端消费同一内容模型，减少“App 里正确、导出后丢公式”的分歧。

### 7.3 任务、同步与权限

文件上传成功后建立任务；服务端返回任务标识，客户端使用事件推送或可退避的轮询获取进度。每页处理独立检查点，失败任务仅补处理缺失页。请求和任务都使用幂等标识，重试不会重复建题。供应商失败、超时和超额要有标准化错误，限制重试次数，避免不断计费。

Android 的 WorkManager 用于可恢复的上传、下载和同步，网络约束与退避明确；云端 OCR 和文档生成在上传完成后独立运行，客户端重启后凭任务标识恢复。WorkManager 受到系统调度和厂商省电策略影响，不承诺后台实时执行。Android 16 的长运行 Worker 还可能消耗任务配额，因此首版任务分块、保留检查点，大批用户主动传输另按系统支持评估专用传输任务。[长运行 Worker 限制](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)。

任务进度优先在 App 内展示；用户授权通知时再提供相关任务通知。无推送服务设备仍可在重新打开 App 时查询任务。推送只用于提醒，不能作为任务完成与数据恢复的唯一依据。

本地优先保存用户编辑。离线操作待网络恢复后按幂等队列同步；对同一题的并发修订检测版本冲突，保留两个版本供用户选择。删除生成同步标记，避免其他设备重新上传旧数据。

每个数据库对象和存储资源都执行用户归属校验；短期签名链接只能在授权后生成。OCR/模型密钥留在服务端，不打包进 App。日志默认不记录原始题面和学生身份字段。

原始照片与处理结果单独设保留策略；默认不用于训练，反馈用于改进需要明确选择。删除操作覆盖数据库、原图、裁片、导出文件及派生索引，备份按公开保留周期淘汰。上线前按实际地区和年龄段核查隐私、未成年人数据及内容来源要求。

## 8. 验收、成本与运营

先建立至少 1,000 道人工标注高中题目的验证集，覆盖印刷、手写、多栏、跨页、几何、长公式、三个高中年级和不同教材。按试卷/文件来源拆分调参与验收集，避免同一试卷相邻页造成结果偏高。以下为建议目标，不是已测量结果；不应将部分印刷题成绩推广为所有题目的准确率。

| 指标 | 第一版目标和口径 |
| --- | --- |
| 拆题 | 清晰印刷题主问题边界 precision/recall 均至少 95%；子题单独统计 |
| 公式 | 清晰印刷题公式完全正确率至少 95%，用规范化 LaTeX 对照人工真值；关键符号错误单独报告 |
| 分类 | 已定义首发课程体系内知识点主标签 precision 至少 90%，同时报告覆盖率与待分类率 |
| 人工校对体验 | 单题纠错平均时间、批量确认比例和回退原图次数逐轮下降 |
| 单页导入 | 标准页约 10 题、图片不超过 2 MB，固定网络与并发条件下上传到草稿可用 P95 不超过 15 秒 |
| 搜索 | 约 5,000 道缓存题目，在指定基准设备上本地筛选/搜索 P95 不超过 300 ms |
| 导出 | 标准 50 题文档，在固定资源与并发条件下 P95 不超过 30 秒；参考样张无缺图、裁切或答案串入 |
| 动效 | 基准 Android 真机持续滚动接近设备可用刷新率；低配机先保证流畅，模糊按实测降级，用帧时间与卡顿比例验证 |
| 异常恢复 | 上传中断、任务超时、部分页失败、取消和重启都可恢复，无重复建题或数据丢失 |

手写、复杂图形和高阶公式单独报告，不为未知能力设虚假的统一准确率。测试包括坏文件、空白图、低分辨率、旋转、多栏、跨页、长题、多选、混合语言、超长公式和内存压力。DOCX 样张在目标 Word/WPS 版本验证公式编辑与打印；PDF 样张检查字体、裁边、图形清晰度、题号与答案。

Android 验收矩阵覆盖首版最低版本、Android 12/12L 的模糊边界与发布时主要新版本；覆盖华为/荣耀、小米、OPPO、vivo、三星等实际目标机型中的有/无 Google Play 服务环境。测试 4 GB 内存机型、多图/多页导入、手势与三键导航、横竖屏、分屏、字体放大、相机权限拒绝、URI 授权失效、通知拒绝、进程被系统回收和厂商省电策略。使用 Macrobenchmark、Baseline Profiles 与 release 构建验证启动和列表滚动，避免只用 debug 构建评估性能。

成本按“每页 OCR + 模型调用 + 导出任务 + 存储/带宽”统计，同时观测每道可用题的综合成本。数字文件原生解析、文件去重、裁剪后识别、限制无效重试和按页复用结果可以降低费用。首版设置并发、单次页数和账号月配额，具体值在供应商压测后确定。

可采用免费基础题库与有限云识别额度，订阅提供更多识别额度、云同步和高级模板。收费和价格需要用户访谈与实际成本验证，不直接套用第三方当前价格。关键运营指标为首次成功保存、次日/周留存、校对负担、成功导出和每份可用题集的成本。

## 9. 开发顺序与里程碑

按一名 Android 工程师、一名后端工程师、一名 OCR/导出工程师，设计与测试部分投入估算，第一版约 12–14 周；依赖现成识别服务、明确的首发年级/教材范围和可接受的 DOCX 支持子集。自训练模型或要求高阶公式全覆盖会增加周期；单人承担全部工程时需缩小首发范围或延长周期。

| 时间 | 交付 | 验收条件 |
| --- | --- | --- |
| 第 1–2 周 | Android 工程、设计组件、玻璃性能原型、标注集、OCR 与 PDF/DOCX 纵向验证 | CameraX/选择器真实输入走通；有/无 GMS 流程验证；确认内容模型 |
| 第 3–5 周 | 三种录入、持久任务、校对、Room 题库 | 断网、权限拒绝、进程回收与部分失败可恢复；公式和图形可追溯 |
| 第 6–8 周 | 分类、筛选、题集、排序与导出设置 | 题集多对多正确；用户修正不会被自动覆盖 |
| 第 9–11 周 | PDF/DOCX 产品化、Android 平板/宽窗口、同步与视觉动效完善 | PDF 预览/保存/分享一致；DOCX 可编辑；系统返回与 insets 正确 |
| 第 12–14 周 | Android 真机矩阵、内存与性能压测、OCR 边界案例、数据删除、签名试用包 | 首发验证集和设备通过验收，产生可安装 APK；按渠道需要准备 AAB |

设计与动效原型从第 1 周开始，并随功能交付持续验证。不能把所有视觉和交互问题留到最后。

第一步开发产物应是一条真实数据闭环：导入包含公式、选项与几何图的试卷页 → 拆成可校对题目 → 修改一个指数或不等号 → 自动建议年级与知识点 → 加入题集 → 输出两页可打印 PDF 和带原生公式的 DOCX。这个闭环能够同时验证识别、数据结构、校对和导出，之后再扩大页面数量与题型覆盖。

## 10. Android 发布准备

首发渠道暂按国内 Android 应用市场规划，Google Play 如需发布则另设发布配置；识别服务和账号不绑定某个商店。开发初期提供可安装的内部 APK，发布时使用稳定签名管理、release 优化和可重复构建；Google Play 需要时产出 AAB。正式发布前按目标渠道当前要求确认 targetSdk、权限说明、SDK 清单、隐私内容与签名提交格式。

相机权限在使用时请求；图片与文件走用户选择流程；保存文档使用用户选择的目标 URI。通知是任务提醒的可选授权。App 内浮层不申请 SYSTEM_ALERT_WINDOW，选中文件导入不申请全文件管理权限。缓存与原始资料有独立清理规则，清理缓存不能删除用户尚未同步的草稿或源文件。
